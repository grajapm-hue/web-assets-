# Thayam 7×7 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the 7×7 Thayam board — three rings, five pieces each, and the traditional capture-before-you-turn-inward rule that 5×5 deliberately drops.

**Architecture:** The 5×5 board already uses generic ring geometry (`__thayamRings(N)` works for any odd N and was verified against the approved 7×7 mockup before this plan was written). The work is therefore *generalisation, not reinvention*: lift the handful of hardcoded `5`s out of the board and piece modules, turn the two-ring `lap` model into an N-ring one, and add a second tile and panel that configure the same engine differently.

**Tech Stack:** Same single-file `mathmatrix/beta.html`, ES5, one self-closing IIFE per concern, `window.__thayam*` exports between them.

**Spec:** `docs/superpowers/specs/2026-08-25-thayam-design.md` (Part 1 rules; its "What's still open" 7×7 questions are resolved below)

## Resolved design questions

These were left open in the spec. Decided here, with reasons, before any code:

1. **Ring path.** Concentric rings with an inward pivot at each boundary — the same model 5×5 uses, not a spiral. Verified against the approved mockup (`tools/_mock-thayam-table-7x7.html`): with rings 24/16/8, every colour's gate sits at `colourIndex × ringLen/4` on the outer ring and its second Mount at `+ ringLen/8` along the middle ring. All 8 cells match the mockup exactly. The spec's doubt is answered: no special-casing needed.
2. **Does one capture unlock BOTH inward pivots, or does each ring need its own?**

   **One capture unlocks all inward movement.** The spec says "you cannot move any of your pieces off the outer ring and into the smaller ring… until you have captured at least one opponent's piece" — one capture, one unlock. Requiring a second capture to reach the innermost ring would compound the exact wait that measurement showed is already the worst part of this rule (15 rolls average, 46 worst, on the smaller board). Cheap to revisit: it is one condition in `advancePiece`.

3. **Pieces per player: 5**, per the spec. Flagged as a length risk — see Task 6, which measures real game length and reports it rather than assuming it is fine.
4. **Mount squares: 8**, two per colour (outer gate + middle-ring corner), matching the mockup. The innermost ring carries none, as in the mockup.

## Global Constraints

- 7×7: three rings (24 / 16 / 8 cells) + centre at flat index 24; **5 pieces** per player; **cut-mandate ON**.
- 5×5 keeps its shipped behaviour EXACTLY: two rings (16 / 8) + centre 12, 3 pieces, cut-mandate OFF. Every existing 5×5 test must stay green without modification unless the plan explicitly says otherwise.
- Anti-clockwise ring order `A → D → C → B` everywhere, both boards (`__thayamSideIndex`).
- Each task keeps its own self-closing IIFE; cross-module calls only through `window.__thayam*`.
- ES5 only in `beta.html` (`var`/`function`), 2-space indent.
- Saved games from the shipped 5×5 must not break: the `lap` field changes shape, so restore has to migrate old saves rather than throw them away.

- [ ] **Step 3: Generalise the board module**

In the board IIFE, replace the fixed `rings5` / `realCell` / `SAFE_T` / `CENTER_T` / `buildThayam5x5` with per-N versions built on demand and cached. Key points:

```js
      var boards = {};   // N -> { n, rings, safe, center, cells }
      function boardOf(N){
        if (boards[N]) return boards[N];
        var rings = window.__thayamRings(N);
        var center = Math.floor(N / 2) * N + Math.floor(N / 2);
        var safe = {};
        SIDES_T.forEach(function(side){
          var ci = window.__thayamSideIndex(side);
          safe[realCellOn(N, rings, 0, ci, 0)] = side;                        // the colour's own gate
          /* One step diagonally inward from the gate, which is the ring's own
             corner: ringLen/8 along from the axis. On 5x5's 8-cell middle ring
             that is 1 -- exactly the offset already shipped -- and on 7x7's
             16-cell one it is 2, which is what the approved mockup shows. */
          safe[realCellOn(N, rings, 1, ci, rings[1].length / 8)] = side;
        });
        boards[N] = { n: N, rings: rings, safe: safe, center: center,
                      cells: Array.from({ length: N * N }, function(_, i){ return i; }) };
        return boards[N];
      }
      function realCellOn(N, rings, lap, colourIdx, position){
        var ring = rings[lap];
        var idx = (colourIdx * (ring.length / 4) + position) % ring.length;
        var rc = ring[idx];
        return rc[0] * N + rc[1];
      }
      window.__thayamRealCell = function(lap, colourIdx, position, N){
        var b = boardOf(N || 5);
        return realCellOn(b.n, b.rings, lap, colourIdx, position);
      };
      window.__thayamState = function(N){ return boardOf(N || 5); };
```

`buildThayam5x5` becomes `buildBoard(N)` writing into the right grid element (`#thayamGrid` for 5×5, `#thayam7Grid` for 7×7 — Task 3 adds the second); keep `window.__thayamBuild5x5` as a thin alias so nothing else breaks yet.

### Task 2: N-ring piece engine

**Files:**

- Modify: `mathmatrix/beta.html` (piece-engine IIFE)
- Test: `mathmatrix/tools/check-thayam-pieces.js` (extend)

**Interfaces:**

- Produces: `window.__thayamConfigure({ n, pieces, cutMandate })`; `piece.lap` becomes `'home' | 'finished' | <ring index number>`.
- Consumes: Task 1's `__thayamState(N)` / `__thayamRealCell(..., N)`.

**Why the lap model changes:** today `lap` is `'outer'|'inner'` and `advancePiece` maps it with `piece.lap === 'outer' ? 0 : 1`. That cannot express a third ring. A numeric ring index removes the mapping entirely and is *less* code, not more.

- [ ] **Step 1: Write the failing test**

```js
  // --- 7x7: three rings, and one capture unlocks BOTH inward turns ---
  await ev(`window.__thayamConfigure({ n: 7, pieces: 5, cutMandate: true })`);
  await ev(`window.__thayamNewGame(['A','B','C','D'])`);
  const p7 = await ev(`JSON.stringify(window.__thayamPieces())`).then(JSON.parse);
  ok('7x7 deals 20 pieces (4 players x 5)', p7.length === 20, String(p7.length));

  // parked at the outer ring's last cell with no capture: refused
  await ev(`window.__thayamSetPieces([{ side:'A', idx:0, lap:0, position:23, lastCell: window.__thayamRealCell(0,0,23,7) }])`);
  const blocked7 = await ev(`JSON.stringify(window.__thayamApplyRoll(0, 0, 1))`).then(JSON.parse);
  ok('7x7: no capture yet, so the outer ring will not let go', blocked7.moved === false, JSON.stringify(blocked7));

  // after one capture it may cross, and that SAME capture also unlocks ring 1 -> 2
  await ev(`window.__thayamForceCut('A')`);
  await ev(`window.__thayamApplyRoll(0, 0, 1)`);
  const onMiddle = await ev(`window.__thayamPieces()[0].lap`);
  ok('7x7: one capture lets it turn onto the middle ring', onMiddle === 1, String(onMiddle));

  await ev(`window.__thayamSetPieces([{ side:'A', idx:0, lap:1, position:15, lastCell: window.__thayamRealCell(1,0,15,7) }])`);
  await ev(`window.__thayamForceCut('A')`);
  await ev(`window.__thayamApplyRoll(0, 0, 1)`);
  const onInner = await ev(`window.__thayamPieces()[0].lap`);
  ok('7x7: the same capture also lets it turn onto the innermost ring', onInner === 2, String(onInner));

  // centre still needs an exact roll, now off the innermost ring (8 cells)
  await ev(`window.__thayamSetPieces([{ side:'A', idx:0, lap:2, position:0, lastCell: window.__thayamRealCell(2,0,0,7) }])`);
  const over7 = await ev(`JSON.stringify(window.__thayamApplyRoll(0, 0, 9))`).then(JSON.parse);
  ok('7x7: overshooting the centre is refused', over7.moved === false, JSON.stringify(over7));
  const win7 = await ev(`JSON.stringify(window.__thayamApplyRoll(0, 0, 8))`).then(JSON.parse);
  ok('7x7: an exact roll finishes the piece', win7.won === true, JSON.stringify(win7));

  await ev(`window.__thayamConfigure({ n: 5, pieces: 3, cutMandate: false })`);   // back to the shipped 5x5
```

- Add `var CFG = { n: 5, pieces: 3, cutMandate: false };` and `window.__thayamConfigure = function(c){ ... }` (merging, then `boardOf(CFG.n)` for `SAFE_T`/`CENTER_T`/ring lengths).
